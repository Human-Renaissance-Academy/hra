    환경변수 계약 목록¶

    생성 정본: scripts/_lib/environment-inventory.mjs. 직접 수정하지 말고 node scripts/check-environment-contract.mjs --write-reference로 갱신합니다.

    이 문서는 #282의 저장소 정적 계약입니다. 실제 Vercel·Neon·Blob 설정이나 환경 분리 완료를 증명하지 않습니다. 배포 절차는 배포 안내를 따릅니다.

    Production·Preview·Development는 DB·공개/비공개 Blob·OAuth·세션 비밀값을 서로 공유하지 않습니다. Preview에서 Production 값을 상속하지 않으며, 필요한 격리 자원이 없으면 기능을 끄거나 검증을 중단합니다. 이는 적용할 정책이며 실제 연결을 자동 검증했다는 뜻은 아닙니다.

    동작을 해석할 때¶

    • 보호 자료는 RESOURCE_PRIVATE_BLOB_ENABLED가 true가 아니면 기존 공개 저장소를 선택합니다. true인 상태에서 private 호스트·토큰이 없거나 잘못되면 업로드를 거부하고 공개 저장소로 되돌리지 않습니다. 기존 공개 파일 이전은 별도 #268입니다.
    • 학사 제출은 항상 명시한 Private Blob만 사용합니다. 업로드는 학사·업로드 gate가 모두 true여야 합니다. 정리는 사용자 기능과 독립된 cleanup gate로 실행하며 실제 삭제에는 별도 delete gate가 필요합니다. 기본은 비활성·dry-run입니다.
    • 사이트 메타데이터 주소는 src/lib/site-url.ts가 정합니다. VERCEL_ENV=production이면 VERCEL_PROJECT_PRODUCTION_URL → 고정 운영 주소, 다른 VERCEL_ENV이면 VERCEL_URL → NEXT_PUBLIC_APP_URL/localhost, Vercel 밖이면 production 실행은 고정 운영 주소, 개발은 NEXT_PUBLIC_APP_URL/localhost입니다. 검색 색인은 VERCEL_ENV=production에서만 허용합니다(색인 정책).
    • vercel.json의 유일한 일정은 /api/cron/cleanup-rate-limits, 0 3 * * * (03:00 UTC/12:00 KST)입니다. 세 cleanup API(cleanup-rate-limits·cleanup-academic-uploads·cleanup-mobile-sessions)는 CRON_SECRET 누락 시 503, 인증 실패 시 401입니다. 학사·모바일 세션 cleanup 예약은 승인 전 자동 등록하지 않습니다.
    • 웹 OAuth callback은 환경별 /api/auth/callback/google·/api/auth/callback/kakao입니다. 향후 Mobile deep link·토큰 세션은 별도 설계이며 현재 웹 callback 설정이 모바일 인증 구현을 뜻하지 않습니다.
    • 인증 URL 선택은 위 metadataBase 주소 선택과 별도입니다. Auth.js는 AUTH_URL ?? NEXTAUTH_URL로 origin/basePath를 선택합니다. canonical 값의 빈 문자열도 nullish가 아니므로 호환 별칭을 막습니다. 새 설정은 AUTH_URL·AUTH_SECRET을 사용하며 NEXTAUTH_URL·NEXTAUTH_SECRET은 기존 호환 입력으로 구분합니다.
    • Auth.js의 trustHost 기본값은 !!(AUTH_URL ?? AUTH_TRUST_HOST ?? VERCEL ?? CF_PAGES ?? NODE_ENV !== 'production')입니다. 먼저 선택된 비어 있지 않은 문자열은 false라는 문자열도 true이며, 먼저 선택된 빈 문자열은 false입니다. 미설정과 빈 문자열은 다르므로 예시를 임의로 false 문자열로 채우지 않습니다.
    • Auth.js의 redirect proxy·secret rotation이나 Blob의 OIDC/store ID 등 모든 SDK 옵션을 지원하거나 열거하는 계약은 아닙니다. 새 옵션을 도입하려면 목록·문서·검증을 함께 변경합니다. 공급자 내부의 임의 환경변수까지 정적으로 전수 검사했다고 주장하지 않습니다.
    • 저장소는 .nvmrc와 package.json에 Node 24를 지정하며 앱 CI는 .nvmrc를 읽습니다. 앱 CI의 checkout/setup-node Action은 SHA로 고정하고 작업에는 저장소 읽기 권한만 부여합니다. 이는 저장소 설정의 확인이며 실제 Vercel 실행 버전이나 배포 성공을 증명하지 않습니다.
    • scripts/verify-auth-proxy-http.mjs와 scripts/verify-markdown-boundary.mjs의 여섯 시스템 값 복사는 각각 파일 경로와 전체 식이 일치할 때만 예외로 허용합니다. 새 키·동적 접근은 계약 검사에서 거부합니다. 이 정적 검사는 QA 실행기의 런타임 격리나 작업 디렉터리의 .env 파일 부재까지 증명하지 않습니다.

    검사 범위와 한계¶

    검사는 src, scripts, tests/support, tests/e2e와 명시한 루트 설정 파일의 JS/TS/TSX를 AST로 읽습니다. 단위 테스트의 변조 fixture, 의존성 내부, 실제 .env 및 외부 비밀 저장소를 읽지 않습니다. 운영 스크립트도 목록에 포함하지만 실행하지 않습니다. 새 계산식·별칭·환경 객체 전달은 실패하며 근거 있는 정확한 예외만 추가합니다. 이름 분류와 필수 조건·누락 동작의 의미는 코드 리뷰로 확인합니다.

    node scripts/check-environment-contract.mjs는 실제 값이나 예시의 잘못된 값을 오류에 출력하지 않습니다. 앱 CI에서 npm ci 이후 실행하며 설치 없는 PR/릴리스 정책 job의 계약은 유지합니다. 기존 문서 전체 정비나 #282의 실제 운영 확인까지 완료 처리하지 않습니다.
