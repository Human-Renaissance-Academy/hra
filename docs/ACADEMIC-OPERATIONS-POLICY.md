# 학사 운영 정책 초안 — 출결·교수 검토·수료

> **초안(2026-11-19) — 운영 승인 전 기능 비활성.** 운영 책임자의 2026-11-19 지시("권장안으로 정책 초안 작성 후 그 정책대로 기능 비활성 상태로 구현; 실제 활성화는 승인 후")에 따라 작성한 권장안이다. 이 문서의 병합은 정책 승인이나 운영 활성화가 아니다. #143은 운영 승인 기록이 남을 때까지 열어 둔다.

운영 책임자와 G2/G3 기능(#165·#159·#160·#161·#162·#163)을 구현하는 개발자가 읽는다. 2026-10-13에 운영자가 확인한 사실(교수는 출결을 담당하지 않음, 어드바이저 1명·조교 2명이 돌아가며 출결 체크, 이들의 관리 담당자는 홈페이지 `ADMIN`과 다른 사람)은 [학사 로드맵](ACADEMIC-MANAGEMENT-ROADMAP.md) §1에 있다. 이 문서는 그 사실 위에서 **아직 미정이던 규칙의 권장안**만 정한다. 보존기간은 [개인정보 보존·파기 정책 초안](ACADEMIC-PRIVACY-RETENTION-POLICY.md)을 따른다.

## 1. 결정 요약 (권장안)

| ID | 항목 | 권장 결정 | 근거 |
| --- | --- | --- | --- |
| P1 | 학사 운영 관리자 | 검증된 계정 ID로 따로 지정하는 업무 권한. `ADMIN`·`FACULTY`·`MEMBER` 역할에서 추론하지 않음 | 운영 인력 관리자는 `ADMIN`과 다른 사람(2026-10-13 확인) |
| P2 | 운영 인력 배정 | 기수별 `ADVISOR` 동시 유효 1명, `ASSISTANT` 동시 유효 최대 2명. 시작·종료 시각을 둔 기간 배정 | 기수별 고정·조교 학기 중 교체(확인 사실) |
| P3 | 배정·교체·해제 승인 | 학사 운영 관리자만. 교체는 기존 행 종료 후 새 행 추가. 과거 행 수정·삭제 금지 | 과거 출결 입력자 보존 |
| P4 | 대리 입력 | 불허. 부재 시 같은 기수의 다른 유효 배정자가 입력 | 배정 밖 권한 확장 방지 |
| P5 | 출결 상태 | `PRESENT`(출석)·`LATE`(지각)·`ABSENT`(결석)·`EXCUSED`(인정결석). 행이 없으면 **미입력**이며 결석이 아님 | 미입력과 결석 구분(로드맵 G2 게이트) |
| P6 | 최초 입력 기간 | 수업일(KST) 당일부터 7일 안에 유효 배정자 누구나 입력. 이후 변경은 정정 절차 | 실수 수정 여지와 기록 안정성의 균형 |
| P7 | 정정 | 사유 필수 + 감사 기록 + **요청자와 다른 사람의 2차 승인**(같은 기수 유효 배정자 또는 학사 운영 관리자). 승인 전에는 기존 값 유지 | 1인 임의 변경 방지 |
| P8 | 인정결석 | `EXCUSED` 지정·해제는 학사 운영 관리자 승인만. 증빙 원본은 시스템에 저장하지 않고 확인 방식만 기록 | 최소 수집 |
| P9 | 학생 열람 | 본인 출결만 조회. 정정 요청은 운영 채널로 받고 시스템 정정은 P7 절차 | 소유권 원칙 I1 |
| P10 | 운영 인력 열람 범위 | 배정 기수의 출결 대상 최소 명단(표시 이름·학적 UUID)과 출결만. 과제 파일·평가·다른 기수 불가. 배정 종료 즉시 차단 | 최소 권한 |
| P11 | 교수 과제 검토 | 학사 운영 관리자가 검증된 교수 계정을 **특정 수업(세션)의 검토자로 지정**한 경우, 그 수업에 연결된 과제의 제출물만 열람·피드백. 출결 열람·입력 불가 | 교수 출결 미담당(확인 사실) |
| P12 | 피드백 학생 공개 | 교수 작성 즉시 공개하지 않고 학사 운영 관리자가 공개 처리 | 오기·민감 표현 검토 |
| P13 | 수료 기준 | 기수별 **버전 관리**. 공개 후 버전 내용 불변, 변경은 새 버전 + 사유. 판정에 쓴 버전을 기록 | 소급 변경 방지 |
| P14 | 수료 확정 | 시스템은 보조 계산만. 확정·취소·정정은 학사 운영 관리자가 사유와 함께 수동 처리하고 감사 기록. 자동 수료 없음 | G1 원칙 "시스템이 수료를 자동 판단하지 않음" |

## 2. 학사 운영 관리자 — 최소 범위

학사 운영 관리자는 전역 `users.role`을 늘리지 않고, G1 지정 승인자처럼 **검증된 로그인 계정 ID 목록**으로 지정하는 업무 권한이다. 홈페이지 `ADMIN`이라는 이유로 부여하지 않는다.

| 허용 | 불허 |
| --- | --- |
| 기수별 어드바이저·조교 배정·교체·해제 | 홈페이지 콘텐츠·회원 역할 관리(홈페이지 `ADMIN` 영역) |
| 출결 정정의 2차 승인, 인정결석 승인 | 출결 최초 입력(배정자가 아닌 경우) |
| 교수의 수업별 검토자 지정·해제, 피드백 학생 공개 | 학생 대신 과제 제출 |
| 수료 기준 버전 공개, 수료 확정·취소·정정 | 감사 기록 수정·삭제 |
| 배정 기수 범위 밖 예외 열람(사유·감사 기록 필수) | 승인 없는 일괄 내보내기 |

- 본인이 요청한 정정이나 본인의 수료 기록은 승인하지 않는다(자기 승인 금지).
- 학사 운영 관리자와 G1 지정 승인자(HRA 운영 책임자)가 같은 사람인지는 **미정**이다. 같은 사람이어도 설정과 감사 기록에서 두 권한을 구분한다.

## 3. 상황별 판정 예시

| 상황 | 처리 |
| --- | --- |
| 조교 A가 학기 중 B로 교체 | 학사 운영 관리자가 A의 배정 종료 시각을 기록하고 B의 새 행을 추가. A가 입력한 과거 출결의 입력자는 A로 유지. 종료 시각 이후 A의 요청은 거부 |
| 어드바이저가 수업 당일 결석으로 입력했으나 학생이 지각 | 7일 이내면 유효 배정자가 직접 수정 가능(감사 기록). 7일 이후면 사유를 적어 정정 요청 → 다른 배정자 또는 학사 운영 관리자 승인 |
| 학생이 병원 진단서를 냄 | 운영 인력이 확인 후 `EXCUSED` 요청. 학사 운영 관리자 승인. 진단서 사본은 업로드하지 않고 "진단서 원본 확인" 같은 확인 방식만 기록 |
| 홈페이지 `ADMIN`이 출결 화면 접근 | 거부. 학사 운영 관리자로 별도 지정된 경우에만 2절 범위 허용 |
| 교수가 담당하지 않은 수업의 과제 파일 요청 | 거부(정보 노출 최소화 위해 404) |
| 수료 기준이 학기 중 바뀜 | 새 버전 공개. 이미 확정된 수료 판정은 당시 버전 유지. 재판정은 개별 정정 절차 |

## 4. 운영 승인·법무 확인이 필요한 항목

아래는 이 초안이 권장값을 정했지만 운영 책임자 확인 없이는 확정할 수 없는 항목이다.

- [ ] 학사 운영 관리자로 지정할 실제 사람과, G1 지정 승인자와 같은 사람인지 여부
- [ ] 최초 입력 기간 7일과 정정 2차 승인 요건이 실제 운영 인력(3명)으로 수행 가능한지
- [ ] 지각의 기준 시각(수업 시작 후 몇 분), 지각 누적의 결석 환산 여부
- [ ] 인정결석 사유 목록과 증빙 확인 방식
- [ ] 수료 기준의 실제 내용(출석률·과제 제출률 등)과 첫 버전 공개 시점
- [ ] 교수 피드백의 학생 공개 여부 자체(공개하지 않는 운영도 가능)
- [ ] 출결·수료 기록의 보존기간 — [보존·파기 정책 초안](ACADEMIC-PRIVACY-RETENTION-POLICY.md) 2절의 권장값을 법무·기관 기준으로 확인
- [ ] 운영 인력이 계정 없이 참여하는 경우의 처리(현재 권장안은 검증된 로그인 계정 필수)

## 5. 구현 영향 — 승인 전까지 기능 비활성

모든 후속 구현은 이 권장안에 맞추되 **기본 비활성 설정 뒤에** 둔다. 설정을 켜는 것은 4절 항목의 운영 승인 기록 이후다. 신규 코드는 Application Service·Repository 경계를 따르고 Page·Server Action에서 DB를 직접 호출하지 않는다.
