# 주차별 수업일지 문서·수정본 설계

이 문서는 [#636](https://github.com/Human-Renaissance-Academy/hra/issues/636)의 첫 단계 초안입니다. 웹 자료실에서 PDF와 HWP/HWPX 원본을 한 수업일지로 관리하고, 같은 권한으로 이전 수정본을 열 수 있게 하는 계약을 제안합니다. [#637](https://github.com/Human-Renaissance-Academy/hra/issues/637)은 웹 계약이 격리 환경에서 검증된 뒤 같은 자료를 읽습니다.

## 기록과 수정본

- 기존 수업일지 ID와 `/resources/[id]`를 사용합니다. 기존 Markdown 본문과 사진은 계속 표시하고, 날짜와 제목에서 기존 행의 주차를 추정해 채우지 않습니다. 문서로만 신규 등록할 때는 빈 본문을 허용합니다.
- 새 문서 기록은 기수, 실제 수업일(KST의 달력 날짜), 양의 정수 주차를 필수로 받습니다. 새 화면은 명시적 SQL `date` 값을 사용합니다. 같은 날짜가 기존 화면의 KST 포맷에서도 유지되도록 `class_date`를 서버 시간대에 독립적으로 변환하고 검증합니다. 등록 시각과 버전 등록 시각은 서버가 각각 기록합니다.
- 새 문서 기록에만 `(기수, 달력 날짜, 주차)`를 고유하게 적용합니다. 주차와 달력 날짜는 함께 비어 있거나 함께 채워져야 합니다. 최초 확정 이후 기수·날짜·주차는 고정하며, 기존 관리자 편집에서도 이 값은 유지합니다. DB 제약은 문서형 일지가 참조하는 기수의 삭제를 제한합니다. 기존 Markdown 일지만 참조하는 기수에는 현재 삭제 규칙을 적용하고, 관리자 화면은 차단 사유를 표시합니다.
- 새 문서 등록 화면은 주차·수업일·파일을 먼저 받고, 제목은 수정 가능한 `N주차 수업일지`로 제안합니다. 기존 자료실 목록에서 기수·주차로 찾고 최신본의 파일 형식을 확인합니다. PDF 열기는 PDF가 등록된 경우에만 표시합니다.
- 기록마다 1부터 증가하는 수정본 번호와 선택 입력인 변경 메모를 저장합니다. 수정본은 그 시점의 파일 구성을 명시적으로 참조합니다. PDF 한 개와 HWP 또는 HWPX 한 개까지 가능하고 최소 한 개가 필요합니다. 한 형식만 바꾸면 다른 형식은 직전 버전의 검증된 파일을 참조합니다. 파일만 제거하는 기능은 첫 구현에서 제공하지 않습니다.
- 파일 객체와 수정본의 연결을 분리합니다. 파일 객체에는 서버가 발급한 저장 키, 검증된 형식·크기, 표시 파일명, 업로드 시각을 둡니다. 수정본과 파일 연결은 같은 기록의 객체만 참조할 수 있고 형식별 슬롯은 수정본당 하나입니다. 최신본은 해당 기록의 가장 큰 확정 버전이며, 목록 항목은 기록당 한 개입니다.
- 등록과 수정본 확정은 한 PostgreSQL 함수에서 원자적으로 처리합니다. 현재 권한을 확인하고, 같은 주체의 이미 처리된 요청 키와 입력이면 기존 결과를 반환합니다. 같은 키에 다른 입력은 거부합니다. 첫 등록은 기수·날짜·주차 고유 제약으로 경합을 처리하고 충돌 시 열람 가능한 기존 기록을 안내합니다. 수정은 기존 기록 잠금 뒤 최신 버전과 요청의 기준 버전을 비교합니다. 두 경로 모두 사용 가능한 검증 의도만 소비하며, 확정 전에는 파일을 노출하지 않습니다.

## 인가와 파일 처리

| 행위 | 서버 확인 |
| --- | --- |
| 목록·상세·이전 버전·다운로드 | 승인된 회원에게 [공동 수업일지 열람 정책](../resource-access-policy.md)을 적용합니다. 기수 필터는 검색 조건입니다. |
| 신규 등록 | 현재 DB 역할과 기수를 확인합니다. 학생은 실제 배정 기수를 사용합니다. 교수와 관리자는 기존 작성 범위에서 기수를 선택합니다. 미배정 학생과 승인 대기 계정은 등록할 수 없습니다. |
| 수정본 확정 | 작성자 또는 기존 웹 관리자 수업일지 관리 권한을 확인합니다. 학생 작성자에게도 현재 기수 조건을 다시 적용합니다. |
| 보호 다운로드 | 현재 세션, 기록, 확정 버전, 해당 버전의 파일 연결을 같이 확인합니다. 파일 키와 원본 Blob URL은 응답 DTO에 포함하지 않습니다. |

새 파일 저장은 모든 환경에서 설정된 비공개 저장소를 전제로 합니다. 발급 전 현재 쓰기 권한을 확인하고 사용자·기록 또는 신규 등록 요청·형식 슬롯·만료 시간에 묶은 의도를 예약합니다. 서버가 저장소·객체 키·바이트 제한과 문서 형식을 확인하고 확정 시 권한을 다시 확인한 뒤 해당 의도를 한 번만 소비합니다. 브라우저 MIME이 비어 있거나 일반 바이너리인 경우에도 서버의 제한된 콘텐츠 검증을 통과해야 합니다. 기존 PDF/HWP/HWPX 형식 판별기는 재사용 후보이며, 과제 제출 인가·의도 테이블은 수업일지의 저장 계약과 분리합니다.

파일별 크기 제한은 격리 검증에서 결정하고 화면 안내·토큰·서버 검증에 같은 값을 사용합니다. 업로드 취소와 파일 형식 오류에는 다시 시도할 수 있는 안내를 표시합니다.

다운로드는 저장된 검증 결과를 사용해 보호 경로에서 전달합니다. 검증된 PDF의 브라우저 표시에는 기존 인라인 PDF 응답·CSP 정책을 적용하고, HWP/HWPX는 첨부로 전달합니다. 공유에는 인증이 필요한 기존 상세 페이지 URL을 사용합니다. 취소·만료 의도 정리와 확정 파일의 보존·파기는 별도 경로입니다. 공용 파일 원장과 정리를 재사용하면 기존 DB와 새 설치의 참조 뷰 모두에 전체 수정본을 포함합니다. 확정 결과를 확인하지 못했거나 이전 수정본이 참조하는 파일은 정리 대상이 될 수 없습니다. 보존 정책과 파일 참조 처리가 마련될 때까지 서비스와 DB 제약에서 문서형 일지의 물리 삭제를 거부합니다.

## 구현 순서와 수용 기준

1. **DB 계약.** 주차·날짜와 수정본을 추가하는 SQL을 격리 PostgreSQL에서 검증합니다. 신규 설치와 기존 Markdown·사진 행이 있는 설치, 재실행, 적용 실패의 전체 롤백, 중복·동시 확정과 기존 삭제 경로 차단을 확인합니다. 운영 적용에는 [DB 변경 절차](database-change-procedure.md#db-change-gate)를 적용합니다.
2. **웹과 파일 계약.** 보호 업로드·확정·다운로드 서비스를 먼저 연결하고 기존 자료실 상세와 작성 동선을 확장합니다. 합성 PDF와 HWP 계열 파일로 한 건에 두 형식 등록, 한 형식만 교체한 v2와 v1 다운로드, 재시도·만료·취소·기수 변경, 기록과 무관한 파일 요청 거부를 확인합니다.
3. **회귀와 운영 확인.** 320·390·1280px에서 등록·수정본·다운로드·링크 복사를 하고 기존 Markdown·사진·직접 링크를 확인합니다. 문제 발생 시 문서 쓰기를 중단하고 기존 일지와 확정 버전은 보존할 수 있는지 검증합니다. 운영에서 비공개 문서 기능을 활성화하고 파일을 정리하려면 비공개 저장소 검증 [#268](https://github.com/Human-Renaissance-Academy/hra/issues/268), 보존·파기 기준 [#142](https://github.com/Human-Renaissance-Academy/hra/issues/142), 승인된 DB 적용이 필요합니다. 앱은 확정된 목록·상세·보호 다운로드 계약을 사용합니다.

배포 시 신규 기능은 기본 비활성입니다. 비활성 경로가 기존 열만 읽도록 암묵적 전체 열 조회를 점검하고, 적용 전후 스키마에서 기존 화면을 검증합니다. 운영 적용 승인 후에는 카탈로그와 배포 경계를 확인한 뒤 기능을 활성화합니다.

## 저장 구조 검증 후보

`scripts/migrate-class-log-documents.sql`은 문서 기록, 파일과 수정본의 저장 구조를 추가합니다. 기존 `class_logs`의 열·행과 일반 일지 조회는 유지합니다. 문서형 일지의 기수와 실제 날짜는 기존 행과 복합 외래 키로 연결합니다. 따라서 문서형 일지는 최초 버전 없이 확정할 수 없고, 이전 수정본이 참조하는 원본은 지울 수 없습니다.

이 SQL은 [DB 소스 목록](database-change-procedure.md#db-change-gate)에 등록된 검토 후보입니다. 같은 SQL을 다시 실행하거나 동명 객체가 있으면 실패하고 그 시도의 변경을 전부 롤백합니다. 새 설치와 기존 일지가 있는 설치에 각각 적용하여 검증하며, 운영 적용에는 별도 승인이 필요합니다.

다음 단계의 서버 쓰기에서는 현재 역할·기수 확인, 업로드 의도 예약·검증·소비, 요청 키 재시도, 기준 버전 경합을 한 확정 흐름으로 연결합니다. 활성화 전에는 관리자 편집이 문서형 일지의 기존 날짜와 기수를 덮어쓰지 않는지, 참조 중인 일지나 기수를 지울 때 화면에 차단 사유가 표시되는지 검증합니다. 앱 연결 역할도 일반 행 접근에 필요한 권한만 가져야 합니다. 저장 구조만 설치된 상태에서는 웹·Android가 문서 등록이나 다운로드를 시작하지 않습니다.

## 웹 연결 및 활성화

`scripts/migrate-class-log-document-requests.sql`은 첫 저장 구조 SQL 이후 적용하는 예약·확정 후보입니다. 두 SQL의 설치 여부와 앱 DB 역할의 권한을 승인된 대상에서 확인한 뒤에만 `CLASS_LOG_DOCUMENTS_ENABLED=true`로 활성화합니다. 등록·수정본 확정은 별도 `CLASS_LOG_DOCUMENT_WRITES_ENABLED=true`를 함께 요구합니다. 기본값은 둘 다 `false`입니다. 쓰기만 끄면 이미 확정된 파일과 이력을 계속 읽을 수 있습니다.

웹은 파일당 50MiB 상한을 적용합니다. 서버가 예약한 객체만 비공개로 직접 업로드하고, 실제 파일을 서버에서 다시 검증한 뒤 버전을 확정합니다. 버전과 파일은 기존 일지 상세에서 내려받으며 공유 주소는 기존 상세 URL입니다. PDF에는 별도 브라우저 열기와 첨부 다운로드 경로를 제공합니다. 실제 브라우저 뷰어 호환성은 활성화 전 확인합니다.

만료된 예약은 확정할 수 없습니다. 미완료 비공개 객체와 예약의 실제 정리는 보존 기준과 #268 운영 검증을 바탕으로 작성 경로의 활성화 전에 확정합니다. 초기 연결에는 자동 제거 스케줄을 추가하지 않습니다. 계정 삭제 뒤 남는 예약 키의 보존·파기를 이 정리 범위에 포함합니다.

운영용 웹 빌드 뒤 `HRA_TEST_PG_BIN=<격리 PostgreSQL 실행 파일 디렉터리> node scripts/verify-resources-responsive.mjs --class-log-documents`를 실행하면 합성 회원 세션과 확정 이력으로 320·390·1280px 화면의 주차 필터, 최신본·이전본 링크, 수정본 폼과 상세 주소 복사를 확인합니다. 실제 저장소 전송은 이 검증의 범위 밖이며 #268 활성화 검증에서 확인합니다.
