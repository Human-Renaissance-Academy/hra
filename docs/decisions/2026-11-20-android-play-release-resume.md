# 결정 기록: Android Google Play 출시 추진 재개 (2026-11-20)

> **상태: 확정된 개발 방향** · 결정일: 2026-11-20 · 결정자: 프로젝트 소유자 · 후속 이슈: [#576](../../issues/576)
>
> 2026-11-19 [모바일·API 동결 결정](2026-11-19-mobile-api-freeze.md)(#491)을 **Android Google Play 출시와 그에 필요한 API 변경에 한정하여 대체(supersede)** 합니다. 해당 과거 결정의 배경과 당시 중단된 이슈 이력은 보존합니다. 본 결정은 Play 실제 공개·외부 계정/키 생성·운영 DB 변경의 자동 승인으로 간주하지 않습니다.

## 1. 결정

HRA 웹과 `apps/mobile`의 기존 React Native/Expo Android 앱을 함께 유지합니다. Android 앱의 Google Play 배포를 목표로, 릴리스 필수 UX/보안/인증/파일 작업과 `/api/v1`·`packages/contracts`의 **필요한 변경만** 재개합니다. 웹은 기존 Vercel Production을 유지하고 모바일은 EAS 수동 빌드 + Google Play 수동 제출을 원칙으로 합니다.

- Android: 내부 실기기 확인 → EAS signed AAB → Play 내부 테스트 → 필요한 비공개 테스트 → 프로덕션 심사/출시
- API v1 및 모바일 세션: Android 기능에 필요한 호환성/보안 보완을 다시 허용, 이전 동결 때문에 필요한 변경을 금지하지 않음
- iOS App Store, Push, 무인 CD, 무분별한 신규 API, monorepo 재편 및 `apps/web` 이동은 **이번 Android 출시의 선행조건 아님**. 별도 수요·비용·결정이 있을 때 진행
- 운영 보안: #142 개인정보 보존·파기, #268 Private Blob, #279 Preview/Production 격리, #280 DB 백업/복구/마이그레이션 게이트를 우회하지 않음

## 2. 과거 이슈의 의미

- #491은 **2026-11-19 당시 동결 결정을 내린 완료 기록**으로 계속 닫아 둡니다.
- #274(Android MVP)와 #283(EAS/CD)은 당시 **not planned로 종료된 이력**을 보존합니다. 재개 실행은 #576~#583으로 관리합니다. 과거 완료/중단 기록을 출시 통과 증거로 대체하지 않습니다.
- #573의 내부 설치용 APK는 공개 debug keystore로 서명되므로 **Google Play에 업로드하거나 외부 배포하지 않습니다**.

## 4. 모바일 배포 수단

현재 `apps/mobile/eas.json`의 `production` 프로필과 `.github/workflows/mobile-eas-build.yml`의 `mobile-production` 보호 환경을 사용합니다. AAB를 빌드해도 **자동 제출하지 않으며**, Play Console 제출·결제·계정 설정은 명시적 운영자 확인을 거칩니다. 실제 계정·원격 환경 변수의 일치, target SDK, 개인정보·심사 정책은 제출 시점에 다시 확인합니다.

## 5. 운영 원칙

1. 웹 운영 안정성/자료 접근·인증 보안은 출시 일정 때문에 약화하지 않습니다.
2. 새 Android 기능도 실사용·최소 제품 범위와 검증 가능성에 한정합니다.
3. 출시 차단 이슈가 남아 있으면 스토어 심사를 요청하지 않습니다.
4. 스토어 출시 후 취약점 대응·버전 상승·세션 폐기·장애 연락 경로의 담당자를 둡니다.
