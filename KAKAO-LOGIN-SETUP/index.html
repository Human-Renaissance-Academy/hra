    카카오 로그인 설정 가이드¶

    카카오 로그인을 연결하려면 카카오 앱 설정, 사이트 환경 변수, 실제 로그인 확인이 모두 필요합니다. 이 문서는 2026-10-18에 확인한 공식 문서와 현재 HRA 인증 코드를 기준으로 설명합니다. 콘솔의 메뉴 표현이 바뀌면 아래 공식 문서에서 항목 이름을 확인합니다.

    카카오 로그인은 OAuth 방식으로 동작합니다. 사용자는 카카오에서 인증하고, 카카오는 결과를 HRA의 콜백(callback) 주소로 돌려보냅니다. 카카오 계정과 HRA 계정의 연결 정보는 카카오 사용자 ID를 기준으로 유지합니다.

    1. 설정할 환경과 기존 앱 확인하기¶

    먼저 현재 서비스가 사용하는 카카오 앱과 담당자를 확인합니다. 기존 운영 앱을 새 앱으로 바꾸면 사용자 식별과 연결에 영향을 줄 수 있으므로, 로그인 오류를 해결하려고 운영 앱부터 새로 만들지 않습니다.

    환경 준비할 것
    로컬 개발 승인된 개발·테스트용 카카오 앱 설정과 개발 DB
    Preview 테스트할 주소가 정해진 검증 환경과 해당 콜백 주소
    Production 기존 운영 카카오 앱, 운영 사이트 주소, 변경 담당자

    개발과 Preview에 운영 키를 일괄 복사하지 않습니다. 별도 테스트 앱을 사용하는 경우에는 카카오의 테스트 앱 안내를 따르고 테스트 계정·권한을 확인합니다. 운영 앱과 테스트 앱의 사용자 연결 정보를 서로 같다고 가정하지 않습니다.

    앱이 아직 없는 신규 서비스라면 운영 담당자가 Kakao Developers에서 실제 서비스 정보로 앱을 만들고 소유·관리 권한을 정합니다. HRA가 이미 운영 중이면 기존 앱을 먼저 확인합니다.

    2. 카카오 앱에서 설정하기¶

    공식 기준: 카카오 로그인 사전 설정, 앱과 플랫폼 키 설정.

    로그인 사용 설정과 REST API 키¶

    1. 대상 앱의 카카오 로그인 → 사용 설정에서 로그인 기능을 켭니다.
    2. 앱 → 플랫폼 키 → REST API 키에서 해당 환경이 사용하는 키를 선택합니다.
    3. REST API 키 값을 HRA의 AUTH_KAKAO_ID에 사용할 값으로 확인합니다. JavaScript 키나 어드민 키와 혼동하지 않습니다.
    4. 선택한 REST API 키의 클라이언트 시크릿을 확인합니다. 현재 공식 문서에서는 REST API 키를 만들 때 클라이언트 시크릿이 기본 활성화됩니다. 기존 키의 상태도 직접 확인합니다.

    Client Secret(클라이언트 시크릿)은 HRA 서버가 카카오에 자신을 증명하는 비밀값입니다. AUTH_KAKAO_SECRET에 넣으며 브라우저용 공개 환경 변수나 저장소에 적지 않습니다.

    로그인 리다이렉트 URI¶

    선택한 REST API 키에서 카카오 로그인 리다이렉트 URI를 등록합니다. 형식은 다음과 같습니다.

    사이트의 기준 주소/api/auth/callback/kakao

    예시는 실제 설정값이 아니며 사용하는 주소로 바꿉니다.

    용도 예시
    기본 포트의 로컬 개발 http://localhost:3000/api/auth/callback/kakao
    고정된 검증 주소 https://preview.example.com/api/auth/callback/kakao
    운영 주소 https://www.example.com/api/auth/callback/kakao

    요청의 프로토콜, 도메인, 포트, 경로와 끝의 슬래시가 등록값과 일치해야 합니다. 로그아웃 리다이렉트 URI는 다른 설정이므로 로그인 콜백을 그곳에만 등록하면 안 됩니다. Preview 주소가 매번 바뀐다면 담당자가 테스트할 고정 주소 또는 승인된 등록 방식을 정합니다.

    동의 항목¶

    카카오 로그인 동의 화면에서 요청하는 정보는 앱에 허용된 동의 항목(scope)과 일치해야 합니다. 이메일 제공이 항상 가능한 것은 아닙니다.

    현재 HRA의 AUTH_KAKAO_EMAIL_SCOPE=true 설정은 account_email, profile_nickname, profile_image를 요청합니다. 이 설정을 켜기 전에는 세 항목의 사용 권한과 동의 설정을 확인하고, 이메일 동의 운영 절차를 먼저 완료합니다.

    콘솔에서 동의 항목을 설정했다는 이유만으로 신규 가입·기존 계정의 모든 이메일 처리 검증이 끝난 것은 아닙니다. 코드 검토에서 남은 조치와 회귀 검증을 담당자와 확인하고, 승인 전에는 해당 설정을 활성화하지 않습니다.

    3. HRA 환경 변수 설정하기¶

    대상 환경에 다음 값을 설정합니다.

    AUTH_KAKAO_ID=
AUTH_KAKAO_SECRET=
AUTH_KAKAO_EMAIL_SCOPE=false

    ID와 Secret에는 2단계에서 확인한 같은 REST API 키에 속한 값을 넣습니다. false는 이메일 추가 요청을 별도 활성화하지 않는 기본 설정이며, 카카오 응답에 이메일이 절대 없다는 뜻은 아닙니다.

    • 로컬: 비공개 .env를 수정하고 개발 서버를 다시 시작합니다.
    • Vercel: 대상 프로젝트의 환경 변수에서 적용 환경을 골라 저장하고, 변경값을 사용하는 배포를 다시 실행합니다. 자세한 환경 구분은 배포 안내를 따릅니다.

    현재 src/lib/auth.ts는 ID와 Secret이 모두 비어 있지 않을 때 카카오 제공자를 등록하고 src/lib/kakao-provider.ts로 설정을 구성합니다. 로그인 화면도 이 등록 여부를 사용합니다. 예제 문자열을 남겨 두면 실제 키가 없어도 버튼이 보일 수 있습니다.

    4. 성공 확인하기¶

    담당자가 허용한 테스트 계정으로 다음 결과를 확인하고, 확인한 환경·배포·일자를 운영 기록에 남깁니다.

    1. /login에 카카오 로그인 버튼이 보입니다.
    2. 버튼을 누르면 의도한 카카오 앱의 로그인·동의 화면이 열립니다.
    3. 동의 후 등록한 HRA 콜백으로 돌아오고 로그인이 완료됩니다.
    4. 기존 계정은 기존 HRA 사용자로 연결되며, 새로운 계정은 승인 대기인 PENDING으로 생성됩니다.
    5. 로그아웃 후 다시 로그인해도 다른 계정이나 중복 계정으로 바뀌지 않습니다.
    6. 이메일 추가 요청을 승인받아 켰다면 이메일 동의 확인 항목을 별도로 확인합니다.

    버튼 표시만으로 인증이 완료되었다고 기록하지 않습니다. 실제 회원 정보·키·토큰·콜백의 인증 코드는 공개 이슈에 첨부하지 않습니다.

    5. 오류가 나면 확인할 것¶

    증상 확인할 것
    카카오 버튼이 안 보임 대상 환경의 ID·Secret 두 값, 서버 재시작 또는 새 배포의 적용 여부
    KOE004 대상 카카오 앱의 로그인 사용 설정
    KOE006 요청한 로그인 콜백과 콘솔 등록값의 정확한 일치 여부
    invalid_client 올바른 앱·REST API 키·Secret 조합, Secret 활성화와 갱신 상태
    invalid_scope 요청하는 동의 항목과 앱에 허용된 항목, 이메일 운영 절차의 선행 조건
    카카오 인증 후 HRA에서 거부 HRA 서버의 오류 종류, 기존 계정 연결 상태, DB·요청 제한 설정
    기존 카카오 사용자만 로그인 실패 현재 바인딩 상태를 담당자가 확인합니다. 기존 계정 바인딩 복구를 일반적인 로그인 해결 명령처럼 반복 실행하지 않습니다.

    이메일 설정 변경 후 invalid_scope가 생기면 해당 환경의 AUTH_KAKAO_EMAIL_SCOPE를 false로 되돌리고 재배포한 다음 기본 로그인도 다시 확인합니다. 다른 인증 오류까지 이 설정 하나로 해결된다고 가정하지 않습니다.

    6. 도메인이 바뀔 때¶

    운영 담당자가 새 주소의 로그인 콜백을 먼저 등록하고 해당 환경의 사이트 주소 설정을 맞춥니다. 새 주소에서 실제 로그인을 확인한 뒤, 더 이상 사용하는 곳이 없는 기존 콜백만 정리합니다. 키를 새로 발급하거나 운영 카카오 앱을 교체해야 하는 작업과는 구분합니다.

    변경 이력¶

    일자 기록
    2026-04-26 기존 문서에는 카카오 콘솔 개편을 반영하고 Playwright로 실제 콘솔 화면의 위치를 확인했다는 작업 기록이 있습니다. 당시 기록으로 보존합니다.
    2026-10-18 공식 문서와 현재 코드로 설정 순서를 재검토했습니다. 환경 구분, 실제 로그인 확인, 이메일 동의 선행 절차를 보강했습니다. 이번 문서 검토에서 운영 콘솔 설정이나 실제 로그인 성공을 새로 확인한 것은 아닙니다.
