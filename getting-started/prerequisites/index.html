    사전 준비 — 개발 도구와 계정 준비하기¶

    이 문서의 목표는 내 컴퓨터에서 HRA 코드를 읽고 실행할 준비를 마치는 것입니다. 사이트 운영 권한이나 운영 데이터베이스 접속 권한은 개발 도구 설치와 별개입니다.

    처음 보는 용어는 기초 용어집에서 확인할 수 있습니다.

    1. 필요한 도구 설치하기¶

    도구 하는 일 준비 방법
    Git 코드의 변경 이력을 저장하고 팀의 변경을 가져옵니다. Git 공식 사이트에서 설치합니다.
    Node.js 개발 서버와 검사 명령을 실행합니다. Node.js 공식 사이트에서 24.15.0 이상인 24 계열 버전을 선택합니다.
    npm 프로젝트가 사용하는 외부 패키지를 설치합니다. Node.js와 함께 설치됩니다. 별도 설치부터 할 필요는 없습니다.
    VS Code 파일을 읽고 수정하는 편집기입니다. VS Code 공식 사이트에서 설치합니다. 다른 편집기도 사용할 수 있습니다.
    GitHub 계정 이슈를 작성하고 변경을 PR로 제출합니다. GitHub에서 계정을 만들고 이메일을 인증합니다.

    LTS(Long Term Support)는 보안 수정 등을 장기간 제공하는 Node.js 버전입니다. 프로젝트는 지원 중인 Node.js 24.15.0 이상(24 계열)을 사용합니다. CI(Continuous Integration)는 GitHub에서 자동 실행하는 검사입니다. .nvmrc는 24.15.0, package.json의 engines.node는 ^24.15.0이며 앱 CI와 형식 검사 CI도 Node 24를 사용합니다. 지원 상태는 Node 공식 일정을 확인합니다.

    jsdom 31의 Node 요구 조건 때문에 24.14 이하는 지원하지 않습니다. 로컬과 앱 CI는 .nvmrc의 24.15.0으로 검증합니다. Vercel은 공식 Node 버전 정책에 따라 ^24.15.0을 24 계열로 해석하고 minor·patch 버전을 자동 갱신하므로 정확한 patch 고정을 보장하지 않습니다.

    npm run build는 prebuild에서 실제 Node 버전을 출력하지만, 현재 운영 Vercel 프로젝트·배포의 런타임 일치 여부는 미확인입니다.

    공개 저장소를 읽거나 복제하는 데는 관리자 초대가 필요하지 않습니다. 팀 저장소에 작업 브랜치를 올리려면 쓰기 권한이 필요합니다. 관리자의 초대를 받은 경우 수락하고, 외부 기여라면 개인 계정에 복사한 저장소인 포크(fork)를 사용하는지 먼저 확인합니다.

    2. 터미널 열고 설치 확인하기¶

    터미널은 명령어를 입력해 프로그램을 실행하는 창입니다. 이 문서의 명령어 예시는 다음 환경을 기준으로 합니다.

    • macOS: 터미널 앱
    • Windows: Git 설치 시 함께 제공되는 Git Bash
    • Linux: 사용 중인 터미널

    PowerShell은 파일 복사 등 일부 명령이 다릅니다. 처음이라면 Windows에서도 Git Bash를 사용하면 문서의 명령을 그대로 따라갈 수 있습니다.

    새 터미널을 열고 한 줄씩 실행합니다.

    git --version
node --version
npm --version

    세 명령 모두 버전을 출력하고, Node.js가 v24.15.0 이상인 24 계열이면 이 안내의 도구 준비가 끝난 것입니다. npm의 주 버전은 Node.js 버전과 같을 필요가 없습니다.

    VS Code의 확장 기능은 선택 사항입니다. 한국어 메뉴가 필요하면 Korean Language Pack, Tailwind 클래스 자동 완성이 필요하면 Tailwind CSS IntelliSense, 편집 중 코드 진단이 필요하면 ESLint를 설치합니다.

    3. 개발용 서비스 연결 준비하기¶

    HRA는 데이터베이스(DB)에 회원과 게시글을 저장하고, Blob 저장소에 업로드한 파일을 보관합니다. 프로그램만 설치해도 이 서비스가 자동으로 만들어지지는 않습니다.

    운영 담당자와 다음 항목을 확인합니다.

    • 작업에 사용할 개발용 DB와 필요한 테이블·DB 함수가 준비되어 있는지
    • 로그인이나 업로드를 시험한다면 개발용 계정과 해당 서비스 설정을 받을 수 있는지
    • 설정값을 어떤 승인된 경로로 전달받을지

    내 컴퓨터의 실습에는 운영 DB와 운영 파일 저장소를 연결하지 않습니다. 환경 변수 설정과 확인 방법은 프로젝트 받아오기에서 이어집니다.

    막힐 때¶

    증상 먼저 확인할 것
    command not found 또는 is not recognized 설치를 마친 뒤 터미널을 다시 엽니다. 계속되면 해당 프로그램의 설치 경로 설정을 확인합니다.
    Node.js가 다른 버전으로 나옴 이미 설치된 버전이나 버전 관리 도구가 있는지 확인하고 24.15.0 이상인 24 계열로 전환합니다.
    폴더 쓰기 권한 오류 내 계정이 소유한 작업 폴더를 선택합니다. 관리자 권한으로 설치 명령을 반복하지 않습니다.
    GitHub에 브랜치를 올릴 수 없음 초대 수락 여부와 저장소 쓰기 권한, 포크 사용 여부를 확인합니다.
