    자료실 파일 접근 정책 (#101)¶

    이 문서는 보호 자료를 어디에 저장하고 어떤 계정에 전달할지 정하는 정책과 전환 절차입니다. 코드 지원, 환경 설정, 기존 파일 이전은 각각 확인해야 할 단계입니다. 문서 확인일은 2026-10-18이며 운영 설정이나 실물 파일의 현재 상태를 재확인했다는 뜻은 아닙니다. 운영 완료 증거는 #268에서 관리합니다.

    Blob은 파일의 실제 내용을 저장하는 곳입니다. 공개 Blob은 주소를 가진 사람이 읽을 수 있고, 비공개 Blob은 서버가 권한을 확인한 뒤 가져와 전달합니다. 여기서 파일 바이트는 PDF·이미지의 실제 내용을 뜻합니다. DB의 제목이나 목록을 가리는 것만으로 파일 내용이 보호되지는 않습니다.

    결정¶

    회원용과 교수용은 화면 목록뿐 아니라 파일 바이트의 접근 범위를 뜻한다. 공개 Blob URL의 무작위 접미사는 주소 추측을 어렵게 할 뿐 인가를 제공하지 않는다. 승인 전 계정·비로그인 사용자가 URL만으로 열 수 있는 저장소에는 자료실 파일을 두지 않는다. 자료실 공동 콘텐츠의 열람 범위는 자료실 공동 자료 접근 정책을 따른다.

    파일 유형 파일을 읽을 수 있는 계정 저장·전달 정책
    교수용 강의자료 ADMIN, FACULTY 비공개 Blob, 매 요청 역할 검사 후 같은 출처에서 전달
    학생용 강의자료 ADMIN, FACULTY, MEMBER 비공개 Blob, 매 요청 역할 검사 후 같은 출처에서 전달
    가이드북, 주차별 텍스트 문서·첨부 이미지, 수업일지 첨부 이미지 ADMIN, FACULTY, MEMBER 비공개 Blob, 매 요청 역할 검사 후 같은 출처에서 전달
    공개 모집 포스터, 교수진 사진, 갤러리, 공개 수료생 이야기의 이미지 누구나 공개 Blob 허용
    본문 편집기의 이미지 업로드 API에서 만든 이미지 공개 페이지에 게시할 자산으로만 취급 현재는 공개 Blob이다. 자료실의 비공개 첨부 경로로 재사용하지 않는다. 본문에 외부/공개 이미지 URL을 붙이면 그 이미지는 이 정책으로 보호되지 않는다.

    과거 확인 기록¶

    2026-10-14 읽기 전용 확인 시 DB에 강의자료 1건과 가이드북 1건이 있었다. 2026-10-15 비공개 저장소를 별도 접두어로 프로젝트에 연결했다. 당시 기록은 hra-private-resources를 hra-website의 Production, Preview, Development에 RESOURCE_PRIVATE 접두어로 연결한 상태를 설명한다. 기존 파일의 비공개 전환이 완료됐다는 뜻은 아니다.

    이 과거 연결 기록을 앞으로 모든 환경이 저장소를 공유하라는 지침으로 사용하지 않는다. 새 환경 구성과 분리는 환경 전략 및 #279의 검증 결과를 따른다.

    비공개 저장소 연결¶

    Vercel Production 새 업로드 안전장치 (#268): VERCEL_ENV=production에서 RESOURCE_PRIVATE_BLOB_ENABLED=true가 아니면 resourceUploadStore()가 고정 오류로 실패하고 보호 자료 업로드용 저장소를 반환하지 않습니다. 플래그가 true여도 별도 RESOURCE_PRIVATE_BLOB_HOST와 RESOURCE_PRIVATE_READ_WRITE_TOKEN이 올바르게 구성되지 않으면 동일하게 fail-closed합니다. 기존 공개 Blob으로 자동 fallback하지 않습니다. 브라우저 보호 자료 업로드 사전 확인 API는 이 상황에서 503을 반환합니다. 서버 업로드·업로드 토큰 발급 또한 설정 오류를 통해 중단됩니다.

    이 안전장치는 신규 업로드 경로만 보호합니다. 예전 공개 파일의 DB 참조와 원본 공개 URL이 실제로 삭제되거나 차단된 상태를 증명하지 않으며, #268의 나머지 운영 이전/삭제/권한 검증 절차를 생략하지 않습니다. Next.js에서 NODE_ENV=production은 Preview 빌드에도 적용될 수 있으므로 Production 분기는 VERCEL_ENV=production에 한정합니다. Vercel 밖의 배포는 이 자동 판별로 보호된다고 가정하지 말고 별도 배포 게이트를 구성해야 합니다.

    1. 대상 환경의 보호 자료용 비공개 저장소를 연결해 RESOURCE_PRIVATE_READ_WRITE_TOKEN을 제공한다. 공개 콘텐츠용 BLOB_READ_WRITE_TOKEN과 용도를 구분하고, Preview에 운영 저장소 토큰을 복사하지 않는다.
    2. 해당 저장소의 Base URL 호스트만 RESOURCE_PRIVATE_BLOB_HOST에 등록한다. 토큰과 URL 전체를 이슈·PR·로그에 기록하지 않는다.
    3. 새 버전의 읽기·쓰기 경로가 배포된 뒤 RESOURCE_PRIVATE_BLOB_ENABLED=true를 설정하고 재배포한다. 설정이 완전하지 않으면 보호 자료 업로드를 거부한다. 공개 콘텐츠 업로드는 기존 저장소를 계속 쓴다.
    4. 기존 공개 보호 자료의 복사·검증·DB 조건부 변경·공개 원본 삭제를 순서대로 완료한다. 전환 플래그만 켰다고 기존 공개 URL이 보호되는 것은 아니다.

    전달과 외부 뷰어¶

    • 서버는 저장된 파일 URL이나 사용자가 보낸 URL을 범용 프록시 대상으로 받지 않는다. 자료 종류와 DB ID로 행을 다시 찾고, 현재 DB에 연결된 로그인 계정의 역할과 자료 대상(audience)을 검사한 뒤 그 행의 비공개 Blob만 읽는다. 인증·인가 실패 응답에는 파일 주소와 존재 여부를 담지 않는다.
    • 비공개 응답에는 Cache-Control: private, no-store와 X-Content-Type-Options: nosniff를 설정한다. CDN 공유 캐시를 사용하지 않는다. PDF 미리보기와 다운로드는 같은 권한 검사 경로를 쓴다.
    • 인증·역할 확인을 통과한 요청만 사용자별 조회 빈도 제한(#444)에 기록한다. Web 다운로드와 /api/v1/resources/*, Web 쿠키와 모바일 Bearer가 같은 예산을 공유하며 초과는 429와 Retry-After, 제한 저장소 장애는 파일을 제공하지 않는 503이다. 정책 값과 근거는 API v1 문서를 따른다.
    • Microsoft Office Online에 문서 URL을 전달하면 Microsoft 서비스가 파일을 가져갈 수 있고, 전달된 주소가 뷰어·브라우저 기록에 남을 수 있다. 보호 자료의 Office 외부 미리보기를 중단하고 DOC/DOCX/PPT/PPTX/HWP를 인증 후 다운로드로 제공한다. PDF는 사이트 내부 뷰어로 제공한다.
    • Vercel의 단기 서명 URL도 만료 전에는 링크 소지자가 재사용할 수 있다. 계정 역할 변경 직후 접근 차단을 보장해야 하는 기본 다운로드 경로에는 사용하지 않는다. 제3자 미리보기를 허용하는 별도 정책을 정할 때만 만료 시간과 제3자 제공 범위를 다시 검토한다.

    역할 변경, 링크, 삭제¶

    • 서버는 파일 요청마다 현재 DB 사용자 역할을 반영한 세션과 해당 파일 행의 대상 범위를 검사한다. 계정 삭제·승인 취소 후에는 접근을 차단하고, 역할 강등 후에는 줄어든 허용 범위를 적용한다. 이미 내려받은 사본은 회수할 수 없음을 운영 정책에 명시한다.
    • 파일 주소는 공유 링크가 아니다. 자료실 페이지 URL을 공유해도 수신자의 현재 로그인 권한으로 다시 검사한다. 공개 Blob 원본 주소는 마이그레이션 완료 후 삭제하고, 검색 엔진·메신저·브라우저 캐시에 남은 복사본은 기술적으로 회수할 수 없다고 간주한다.
    • 자료 삭제·교체는 새 비공개 Blob을 저장하고 DB 참조를 확정한 뒤 이전 Blob을 정리한다. DB 실패/응답 유실 시 참조 여부와 소유권 원장을 확인하기 전에 파일을 삭제하지 않는다. 삭제 실패는 재시도 대상으로 기록한다. 백업·보존 기간은 별도 운영 정책을 따른다.

    이전·배포 순서¶

    아래에서 원장은 서버가 관리하는 파일 기록, 해시는 파일 내용의 일치 여부를 비교하는 값, ETag는 저장소가 제공하는 파일 버전 식별자다. 조건부 변경·삭제는 확인한 뒤 파일이나 DB 값이 달라졌다면 덮어쓰지 않고 중단하는 방식이다.

    아래 절차는 DB 참조와 파일을 실제로 바꿀 수 있는 운영 작업이다. DB 변경 절차에 따라 대상·복구 경로·동시 쓰기 조건을 먼저 확인한다. 이 문서 정비 과정에서 운영 명령을 실행했다는 뜻은 아니다.

    scripts/migrate-protected-resource-blobs.mjs는 다음 모드를 구분한다. 세 모드는 차례와 결과를 확인하며 별도로 실행한다.

    명령 효과 다음 단계로 넘어갈 조건
    npm run blob:migrate-protected DB 참조 개수 조회, 파일 변경 없음 대상 DB·비공개 호스트와 확인 필요 참조 점검
    npm run blob:migrate-protected -- --apply 복사·바이트 검증·DB 참조 조건부 변경 앱에서 비공개 사본을 읽고 참조 변경을 확인
    npm run blob:migrate-protected -- --delete-public 조건을 만족하는 기존 공개 원본 삭제 비공개 사본·미참조·소유권·삭제 결과 확인

    기본 조회도 DATABASE_URL과 올바른 RESOURCE_PRIVATE_BLOB_HOST가 필요하다. 변경 모드는 비공개 토큰과 RESOURCE_PRIVATE_BLOB_ENABLED=true가 필요하며 --apply와 --delete-public을 동시에 받을 수 없다. --apply 성공만으로 공개 원본 삭제까지 끝난 것이 아니다.

    --delete-public은 각 비공개 사본의 HEAD 결과가 요청한 URL과 일치하고 크기가 양의 정수인지 먼저 확인한다. 이 HEAD 호출이 실패하거나 결과가 불완전하면 고정 문구로 중단하며 공개 원본을 보존한다. SDK 오류 원문에 포함될 수 있는 보호 URL·자료 이름은 출력하지 않는다. 이 보호 조건과 정상 복사·원장 기록은 소유 임시 DB·합성 Blob 저장소에서 검증했으며, 실제 운영 파일의 이전·삭제 완료 증거는 아니다.

    1. 현재 공개 파일의 DB 참조와 Blob 소유권을 목록화하고, 비공개 저장소를 별도로 연결한다. 운영 파일 URL·내용은 이슈, PR, 로그에 기록하지 않는다.
    2. 읽기 경로가 공개/비공개 참조를 모두 처리하는 버전을 배포하고, 새 보호 자료 업로드는 비공개 저장소로 전환한다. 공개 원본 URL은 화면에 반환하지 않는다. 이 중간 단계에서 기존 공개 URL은 여전히 직접 접근 가능하므로 보안 완료로 표시하지 않는다.
    3. 기존 보호 파일을 비공개 저장소로 복사하고 크기·해시 또는 원본과의 바이트 비교를 확인한 뒤 DB 참조를 조건부로 바꾼다. 행이 동시에 수정됐으면 덮어쓰지 않고 재평가한다. 이전 로그에는 파일명·원본 URL을 남기지 않는다.
    4. 모든 DB 참조가 비공개 URL이고 애플리케이션에서 열림을 확인한 후, 새 보호 자료 업로드가 비공개로 전환된 상태에서 비공개 사본의 존재와 공개 원본의 미참조 상태를 삭제 직전에 다시 확인한다. 소유권 원장에 있는 기존 공개 Blob만 원본 ETag 조건으로 삭제한다. 새 본문에 이전 공개 URL을 붙이면 링크가 깨질 수 있으므로 이전 주소 재사용은 금지한다. 재조회로 잔존 공개 참조와 공개 파일을 확인한다. 삭제 실패나 참조 불일치가 있으면 이슈를 열어둔다.
    5. 비로그인·PENDING·MEMBER·FACULTY·ADMIN으로 학생용/교수용 파일의 목록·상세·파일 응답을 검증한다. 역할 강등·계정 삭제 후 재요청, 링크 공유, PDF 인라인·다운로드, 파일 교체·삭제, 기존 공개 URL의 접근 실패까지 확인한다. 운영 자료 URL이나 본문은 테스트 기록에 쓰지 않는다.

    정상 결과: 필요한 참조가 비공개 저장소를 가리키고, 허용 계정의 파일 응답과 거부 계정의 차단을 확인하며, 이전 공개 원본도 정리된다. 실패하면: 출력의 단계와 대상 환경을 확인하고 이미 바뀐 참조·사본 상태를 재조회한다. 플래그를 되돌리거나 원본부터 삭제해 문제를 우회하지 않는다.

    운영 전환 완료 체크리스트 (#268)¶

    아래 항목은 #268의 완료 조건과 일대일로 대응한다. 운영 작업자가 순서대로 확인하고, 각 항목의 결과(통과/실패 여부와 집계 숫자)만 이슈에 기록한다. 토큰·호스트 전체·파일 URL·사용자 식별자는 기록하지 않는다. 이 체크리스트는 절차를 정리한 것이며 실제 운영 전환이 완료됐다는 뜻이 아니다.

    변경 명령에 앞서 위 이전·배포 순서와 DB 변경 절차의 대상 환경·작업 권한·백업/복구 경로·동시 쓰기 통제를 확인한다. 이 체크리스트나 적용 플래그가 운영 작업의 승인을 대신하지 않는다. 어느 단계든 조건이 충족되지 않으면 다음 변경 단계로 넘어가지 않는다.

    순서 확인 항목 확인 방법 기록할 결과
    1 대상 환경에 RESOURCE_PRIVATE_BLOB_ENABLED=true, 비공개 호스트, 비공개 토큰이 모두 설정됨 비밀이 아닌 Boolean 플래그의 실제 값이 정확히 true이고 대상 배포에 반영됐는지 확인한다. 호스트·토큰은 설정 여부만 확인하고 값을 공개·복사하지 않는다. 플래그의 true 여부, 두 비밀 설정의 존재 여부, 대상 환경·배포 식별자
    2 보호 대상의 공개 참조 잔존 수 집계 npm run blob:migrate-protected (조회 전용)는 보호 대상 전체의 공개·비공개·미분류 참조 합계를 출력한다. 유형별 수치가 필요하면 별도로 승인된 읽기 전용 집계를 사용한다. 공개·비공개·미분류 참조 합계, 별도 집계 시 그 범위
    3 기존 공개 보호 객체의 비공개 이전과 앱 읽기 확인 npm run blob:migrate-protected -- --apply 후 2번을 다시 실행해 공개·미분류 참조 수가 0인지 확인한다. 허용된 테스트 계정이 대상 배포의 앱 경로에서 비공개 사본을 열고, 이전 전 파일과 크기·해시가 일치하며 응답의 보호 헤더가 유지되는지 확인한다. 실패하면 원본을 보존한다. 이전 건수, 재조회 잔존 수, 허용 계정의 읽기·바이트 일치·보호 헤더 검증 결과
    4 신규 업로드의 비공개 저장 대상 배포의 승인된 테스트 계정으로 합성 보호 자료를 올려 새 참조가 비공개 호스트를 가리키는지 확인한다. 설정이 불완전하면 공개 저장소로 되돌아가지 않고 업로드가 거부되어야 한다. 새 참조의 저장소 종류(공개/비공개), 불완전 설정 거부 검증 결과
    5 공개 원본 삭제 3번의 앱 읽기와 4번의 비공개 업로드를 확인한 뒤 npm run blob:migrate-protected -- --delete-public을 실행한다. 삭제 직전 비공개 사본·미참조·소유권·ETag 조건을 스크립트가 다시 확인하며, 실패한 원본을 임의로 삭제하지 않는다. 삭제 건수, 실패 건수
    6 접근 차단 검증 대상 배포에서 비로그인·PENDING·권한 없는 역할의 앱 API 접근과 토큰 없는 비공개 원본 접근이 거부되며, 이전 공개 URL도 접근할 수 없는지 별도로 확인한다. 아래 실제 HTTP 접근 검증의 31개 검증은 격리 앱·합성 자료의 회귀 증거이며 운영 확인을 대신하지 않는다. 운영 허용·거부 검증 결과와 이전 공개 URL 접근 실패 여부, 격리 회귀 결과는 별도로 기록

    중요: 1번에서 플래그가 꺼진 상태로 두면 새 보호 자료가 공개 저장소에 저장된다. 코드는 플래그가 정확히 true가 아니면 공개 저장소를 선택하므로, 운영 전환 후에는 위 1번과 4번을 배포마다 다시 확인한다. 3번과 5번 사이에 플래그를 되돌리거나 원본부터 삭제해 문제를 우회하지 않는다. 설정 불완전 거부의 장애 주입은 격리 환경에서 수행하고, 운영 플래그·토큰을 일부러 제거해 시험하지 않는다.

    실제 HTTP 접근 검증¶

    fixture는 실제 사용자 자료 대신 검증에 쓰는 합성 데이터다. 이 검증은 파일 전달 경로의 동작을 확인하며, 기존 운영 자료 전부의 이전 완료를 대신 증명하지 않는다.

    scripts/verify-resource-access-http.mjs는 운영 회원을 변경하거나 JWT를 직접 발급하지 않고 실제 Next 서버의 CSRF·credentials 로그인과 다운로드 API를 실행한다. 임시 PostgreSQL에 합성 계정 4개와 학생용·교수용·가이드북 fixture만 만들고, 역할 변경·세션 버전 변경·계정 삭제도 그 임시 DB에서 수행한다.

    앱의 DB 드라이버·인증·권한 코드는 그대로 사용한다. NODE_OPTIONS의 테스트 전용 preload가 정확한 .invalid Neon 엔드포인트만 로컬 psql로 전달한다. \gdesc로 결과 타입을 설명하고 SQL을 한 번 실행한 결과를 설치된 Neon 클라이언트가 해석하므로, 요청 제한 함수의 실제 실행·성공 예약 삭제·중복 컬럼·타입도 검증된다. 운영 Neon 서비스의 네트워크 동작을 재현하는 검사는 아니다.

    전송 어댑터는 단일 SQL 요청만 지원한다. Neon batch 트랜잭션과 여러 요청에 걸친 동일 DB 세션은 재현하지 않는다. 이 접근 검증에 필요한 함수·SQL의 각 요청은 실제 PostgreSQL 트랜잭션 하나로 실행한다.

    실행 준비

    • node_modules가 설치되고 로컬 PostgreSQL 실행 파일이 있어야 한다. 운영 .env를 읽지 않도록 .env, .env.local, .env.development, .env.development.local이 없는 격리 worktree에서 실행한다.
    • tests/support/resource-qa-pdf.mjs의 resourceQaPdfBytes()가 만든 고정 비민감 PDF만 전용 private Blob의 qa/resource-access-http/ 접두어 아래 .pdf 파일로 준비한다. 콘텐츠 형식은 application/pdf이다. 실행기 자체는 Blob을 업로드·수정·삭제하지 않는다.
    • 실행 프로세스에 HRA_QA_PRIVATE_BLOB_URL, RESOURCE_PRIVATE_BLOB_HOST, RESOURCE_PRIVATE_READ_WRITE_TOKEN을 전달한다. URL은 해당 호스트의 전용 QA 경로여야 한다. 선택 항목 HRA_QA_PRIVATE_BLOB_SHA256은 resourceQaPdfSha256()의 값과 같아야 한다. 비밀값은 명령 인자·기록·추적되는 환경 파일·이슈·로그에 기록하지 않는다. 비밀 관리 도구나 권한이 제한된 임시 파일을 사용하고 검증 후 정리한다.
    • 기존 DATABASE_URL, AUTH_SECRET, 소셜 로그인 설정을 상속하지 않는다. 실행기가 테스트 전용 값과 고유한 HTTP 포트·유닉스 소켓을 만든다.
    HRA_TEST_PG_BIN=/path/to/postgresql/bin npm test -- tests/unit/neon-psql-transport.test.ts
HRA_TEST_PG_BIN=/path/to/postgresql/bin node scripts/verify-resource-access-http.mjs

    /path/to/postgresql/bin은 예시 경로이며 실제 설치된 PostgreSQL의 initdb, pg_ctl, psql이 있는 디렉터리로 바꾼다.

    성공 기준

    상태 학생용·가이드북 교수용
    비로그인 307, /login 307, /login
    PENDING 307, /pending 307, /pending
    MEMBER 200 404
    FACULTY·ADMIN 200 200

    허용된 다운로드·PDF 인라인 응답은 고정 PDF의 SHA-256과 바이트가 일치하고 private, no-store, nosniff, 올바른 콘텐츠 형식·다운로드 방식 헤더를 가져야 한다. private URL의 토큰 없는 직접 접근은 403이고, 쿠키 없이 같은 앱 링크를 재요청하면 307이어야 한다. 기존 교수 쿠키도 역할을 MEMBER로 바꾼 직후 교수용 자료에 404를 받고, 승인 취소·세션 버전 변경·계정 삭제도 다음 요청에 반영되어야 한다.

    기본 모드에서 전체 31개 검증이 통과해야 실물 접근 테스트 완료 증거로 사용한다. 상태 코드·검증 이름만 출력하며 쿠키·파일 URL·응답 본문·토큰·trace는 저장하지 않는다. 종료 시 이 실행에서 만든 Next 프로세스와 임시 DB만 정리한다. 전용 QA Blob의 삭제는 파일을 준비한 작업자가 최종 검증 후 수행한다.

    저장소 연결 전에는 다음 명령으로 정상 로그인과 차단 matrix 30개를 먼저 검증할 수 있다. 이 모드의 허용 경로는 저장소 미연결 502를 확인하므로 실물 200 검증이나 이슈 완료 증거로 사용하지 않는다.

    HRA_TEST_PG_BIN=/path/to/postgresql/bin node scripts/verify-resource-access-http.mjs --authorization-only
